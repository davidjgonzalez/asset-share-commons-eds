Asset Share Commons vs. 3M CMAS Requirements

A theme-by-theme assessment of how the Asset Share Commons (ASC) Edge Delivery Services front end — running against an AEM Cloud Service / AEM backend — covers the 191 requirements in the 3M CMAS disposition & fitment workbook, as consolidated in consolidated_requirements_for_claude.md. ("CMAS" is 3M's internal code name for their asset-share portal.)

Source: 3M_CMAS_Requirement_Analysis_Disposition_and_Fitment (191 requirements, with release/category/persona/platform mapping) Assessed against: ASC codebase (blocks/, scripts/asc/core/services/, docs/)

Methodology. This scorecard was built by reading the consolidated theme summary (not the underlying row-level CSV, which wasn't provided) and cross-checking each claim against the actual ASC source — service implementations, block markup, and docs — so every score below is grounded in code, not the requirement wording alone. It is a thematic fit assessment, not a 191-row line-item audit; treat it as the fast, directional pass, and re-run the row-level CSV through the same method for a contractual-grade answer.

Layer matters. ASC is a front end that sits on an AEM backend (Cloud Service or on-prem, depending on the search provider chosen). Several requirements are satisfied elsewhere in that stack, not by ASC's own code — AEM Author's Assets view (ingestion, metadata editing, versioning, approval), its Admin view (permissions, workflow, group config), and Dynamic Media (Scene7 or the newer OpenAPI — rendition generation, smart/AI search, watermarking, video streaming). Scoring these as ASC "gaps" would be misleading, so each theme is tagged with the layer that actually owns it.

The platform counts too. Fit isn't just "does ASC's JS already do this" — Edge Delivery Services (aem.live) itself has native capabilities that close some of these gaps without ASC-specific code: language-prefixed content trees for locale-aware experiences, Live Search for indexing EDS-authored pages (campaigns/programs, as opposed to DAM assets), and CDN/edge configuration for things like IP allow-listing. Where that changes the practical answer, it's called out explicitly in "How to close it" below.

Scope note. The source pack's "Open questions" and "Known limitations" lists are explicitly drawn from the Content Hub BR workbook only — 3M's workbook doesn't carry an equivalent section, so this file sticks to the theme scorecard. See the companion asc-solution-fit-br-contenthub.html for those.
